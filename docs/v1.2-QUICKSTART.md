# AgentScope v1.2 Implementation Quick Start
## Getting Started with Agent-Focused Enhancements

**For:** Developers implementing v1.2 features
**Time:** 5 minutes to understand the approach
**Goal:** Start implementing atomic tasks efficiently

---

## Quick Overview

v1.2 adds 5 major features across 4 weeks:
1. **Enhanced Documentation** - Better formatting, security summary, capability matrix
2. **Agent Security** - 5 validators scanning for security issues
3. **Advanced Analysis** - Delegation chains, tool matrices, skill coverage
4. **Multi-Platform** - Cursor and Gemini scanner support
5. **Templates** - Secure templates for agents/skills/hooks/MCP

**Total:** 26 atomic tasks, ~1,755 lines of code (including tests)

## Common Patterns

### 1. Security Validator Pattern
```typescript
import { z } from 'zod';
import { DreadScore, SecurityFinding } from '../types';

export class YourValidator {
  async validate(config: unknown): Promise<SecurityFinding[]> {
    const findings: SecurityFinding[] = [];

    // 1. Validate schema
    const parsed = YourSchema.safeParse(config);
    if (!parsed.success) {
      return [{
        risk: 'low',
        finding: 'Invalid schema',
        recommendation: 'Fix configuration',
        dread: this.calculateDread({ damage: 2, ... })
      }];
    }

    // 2. Security checks
    if (parsed.data.insecureSetting) {
      findings.push({
        risk: 'medium',
        finding: 'Insecure setting detected',
        recommendation: 'Use secure alternative',
        dread: this.calculateDread({ damage: 6, ... })
      });
    }

    return findings;
  }

  private calculateDread(scores: DreadInput): DreadScore {
    // DREAD = (D + R + E + A + D) / 5
    const total = (
      scores.damage +
      scores.reproducibility +
      scores.exploitability +
      scores.affectedUsers +
      scores.discoverability
    ) / 5;
    return { score: total, breakdown: scores };
  }
}
```

- [ ] **Code:** Implementation matches specification

## Tips for Success

### 1. Start Small
- Pick the smallest task in a phase
- Get one task fully done before starting another
- Build confidence with early wins

### 2. Test First (TDD)
```bash
# Write test
npm test -- --watch <test-file>

# Implement until tests pass
# Refactor
# Commit
```

### 3. Ask for Help
- Unclear acceptance criteria? Open a discussion
- Stuck on implementation? Check similar existing code
- Need design input? Ping in PR

### 4. Document as You Go
- TSDoc comments for public APIs
- Inline comments for complex logic
- Update relevant ADRs

### 5. Keep Tasks Atomic
- If a task grows >150 lines, split it
- One commit per task
- Small PRs merge faster

---

## Common Pitfalls to Avoid

### ❌ Don't Do This
- Combining multiple tasks in one PR
- Skipping tests ("I'll add them later")
- Breaking backward compatibility without discussion
- Adding dependencies without approval
- Implementing features not in the plan

### ✅ Do This Instead
- One task, one PR
- TDD: tests first, then implementation
- Check compatibility with existing tests
- Discuss new dependencies in issue first
- Stick to the plan (or propose changes in discussion)
